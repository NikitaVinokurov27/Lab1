## Что демонстрирует прототип

Две вкладки = два конца пайплайна из ADR.

**1. «Ребёнок занимается» — источник данных**
- Кнопка «Начать заниматься» стартует сессию; раз в 2 сек летит `heartbeat`, активное время
  капает в счётчик (в проде heartbeat = 15 сек).
- **Idle threshold:** нет активности дольше 6 сек → «Простой», время не капает. Открытая
  вкладка ≠ занятие.
- Ответы на задание и кнопки шлют события `task_done / error_review / attempt` — они вживую
  увеличивают счётчики в виджете родителя.
- Справа — лог реального потока событий, уходящего «на сервер».

**2. «Кабинет родителя» — потребитель данных**
- Тумблер **A/B** (из презентации): **Контроль** — текущий кабинет; **Тест** — кабинет + виджет.
- Виджет «Саша вложил в учёбу»: `4 ч 35 мин = 6 школьных уроков`, задания / ошибки / попытки /
  дни, «Ритм недели» столбиками.
- «Посмотреть подробнее» — модалка с живой формулой расчёта.
- «Полный доступ» / «Подробнее о тарифах» — фиксируют **intent-метрику** (переход к покупке),
  которая на проде идёт в расчёт `ΔCR(test) − ΔCR(control)`.

Данные копятся в `localStorage` по ключу `uchi_effort_v1` в схеме `(child_id, week_id)` —
том же контракте, что описан в ADR. Ссылка «сбросить демо-данные» внизу возвращает эталонные цифры.

## Сценарий показа на защите (≈90 сек)

1. Вкладка «Ребёнок» → «Начать заниматься»: «здесь рождаются данные, время капает».
2. Убрать руку с мыши на 5 сек: «открытая вкладка ≠ занятие — сработал idle threshold».
3. Вкладка «Кабинет родителя», тумблер **Контроль → Тест**: «вот наш A/B — слева родитель
   сам собирает картину, справа за 10 секунд видит масштаб труда».
4. «Посмотреть подробнее» → формула; «Полный доступ» → «это событие идёт в ΔCR».
